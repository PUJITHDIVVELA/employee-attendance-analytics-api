# REVIEW.md

List every defect found in the starter `app/main.py` (helpers and endpoints):

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `create_employee` / line 79-84 | Read-before-write check (`find_one`) for `emp_code` uniqueness allows race conditions under concurrent requests. | Concurrent `POST /employees` with identical `emp_code` results in duplicate documents in MongoDB. | Added a MongoDB unique index on `employees.emp_code` at startup and handle `DuplicateKeyError` to return HTTP 409 atomically. |
| 2 | `list_employees` / line 93-94 | `total` counts the whole collection (`count_documents({})`) rather than the filtered result set; `skip` calculation is off by one page (`skip = page * page_size`). | Requesting page 1 with department filter returns total count for all departments and skips page 1 completely. | Updated count to `count_documents(q)` and fixed skip formula to `(page - 1) * page_size`. Sorted results by `emp_code` ascending per contract. |
| 3 | `punch_in` / line 101-105 | Timezone naive handling using local system timezone (`datetime.fromtimestamp`); attendance `date` derived from server time instead of IST business date (R1). | Punching in during UTC early morning creates record under wrong IST date or fails overnight shift date mapping. | Integrated `from_epoch_millis` and explicit `compute_attendance_date` with `Asia/Kolkata` (IST UTC+05:30) timezone logic and overnight shift rules (R1). |
| 4 | `punch_in` / line 104-118 | Read-before-write duplicate date check is vulnerable to concurrent requests; missing schema default fields (`history`, `overtime_minutes`, `half_day`). | Concurrent `POST /attendance/punch-in` requests produce multiple attendance records for the same employee on the same date. | Created compound unique index `("emp_code", "date")` on `attendance_logs` collection and handle `DuplicateKeyError` returning HTTP 409. |
| 5 | `compute_late_minutes` / line 33-37 | Calculates lateness from server local time string replace without timezone alignment; late condition uses `> 10` minutes instead of strictly `> 10:00` (600s) after shift start. | 09:40:01 punch-in for 09:30 shift yields 0 late minutes instead of 10. | Replaced helper with strict elapsed seconds comparison (`elapsed_sec > 600`) against timezone-aware IST shift start. |
| 6 | `compute_work_hours` & `compute_overtime` / line 40-48 | Uses standard Python `round()` (banker's rounding) instead of required half-up rounding (R4/R8); overtime helper hardcodes IST date string and doesn't handle overnight shifts (R1/R3). | Floating hours ending in `.005` round down to even numbers; overnight shift overtime yields negative or wrong elapsed minutes. | Created explicit `round_half_up` helper using Python `Decimal` and updated `compute_overtime_minutes` to calculate overnight shift boundaries correctly. |
| 7 | `list_attendance` / line 145-149 | In-memory sorting and pagination (`docs.sort(...)` and Python list slicing) loads entire `attendance_logs` collection into application memory. | Poor API performance and memory bloat on datasets with ~100,000 documents. | Moved sorting (`.sort([("date", DESCENDING), ("emp_code", ASCENDING)])`), filtering, and pagination (`.skip()`, `.limit()`) directly into MongoDB. |
| 8 | Schema boundaries & Epoch Milliseconds / all endpoints | Returned `_id` or `id` fields in responses; timestamp fields returned ISO/naive datetimes instead of integer epoch milliseconds (R1). | API contract violations against OpenAPI schemas expecting `int64` epoch milliseconds. | Implemented `to_epoch_millis` and `format_attendance_doc` to strictly strip internal `_id` and map all datetimes to integer epoch milliseconds. |
| 9 | `health` / line 72-74 | Returns static `{"status": "ok"}` without checking MongoDB database connectivity. | Health endpoint returns 200 OK even when MongoDB server is completely offline or unreachable. | Added active `db.command("ping")` check returning HTTP 503 if MongoDB is down. |

### Reviewed Non-Defects
- **Absence of `ABSENT` / `LEAVE` creation endpoints**: Verified that no endpoint is supposed to directly create `ABSENT` or `LEAVE` records (they are created via back-office seeding or manual corrections/regularizations).
